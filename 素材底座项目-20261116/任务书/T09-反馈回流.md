# T09 反馈回流

先读 `..\共同约定.md`，再读 `素材标注总纲.md` 第七节（迭代机制）。开工条件：T08 的候选已经有人在用。

## 目的

把“人最后选了什么、换掉了什么、为什么”收回来，变成两样东西：片段的使用记录，和给总控的规则修改建议。

## 输入

- 镜序导出的评价与经验记录（由张艺或李康在镜序里点导出，把文件交给你）。2026-11-16 时它里面有 127 条评价、54 条经验、253 次检索记录。
- 流程包的历史和审批记录（由陈瀚文提供副本）。
- 李康的审片意见：`..\..\..\VIDEO_PRODUCTION_LEARNING.md`（只读）。
- T06 每批的审核结果。

## 步骤

1. **写使用记录。** 每个被采用或被换掉的片段一条，字段按《片段记录格式》第三张表。能对上片段ID 的对上，对不上的只记原片和起止秒。
   完成标准：收到的每条采用、移除、评价记录都落到了一条使用记录上，或者列在“对不上”的清单里。
2. **归因。** 被判“不合适”或被换掉的，按原因分：标签错了 / 标签对但对照表条件不对 / 条件对但画面质量差 / 重复 / 其他。
   完成标准：每条都有归因；“其他”超过两成时，从里面再归纳。
3. **出周报。** 每周一份，一页：
   - 候选被采用的比例，按素材类别分
   - 被换掉最多的 5 类及原因
   - 镜序里已审核启用的经验，哪些应该变成片段库的标签或对照表的条件
   - 规则修改建议，每条写明依据的记录编号
   完成标准：周报里每个数字能追到具体记录。

## 验收标准

- 使用记录只增不改。
- 镜序里的个人偏好只进个人偏好一栏，团队标准和人工事实才进规则修改建议。
- 修改建议全部交总控，由总控决定进不进规则。

## 这个工位特有的上报情形

- 同一个片段被两个人判成相反的结果。
- 镜序里的人工事实和片段库的人工结论冲突（比如同一段，一边确认是微陶泥批刮，一边不是）。

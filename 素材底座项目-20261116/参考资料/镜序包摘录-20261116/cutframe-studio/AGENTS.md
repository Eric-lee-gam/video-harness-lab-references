# CutFrame 工作进度维护

每完成、开始或发现阻塞的环节，核查证据后更新工作区 `outputs/CutFrame流程图/plan.json`。推荐使用 `update_progress.py 任务编号 状态 --evidence "事实证据" --next "下一步或验收标准"`，它保留旧状态与历史并原子写入，再自动重新生成独立流程图。

- 用户纠正：必须独立于剪辑工具，采用泳道、箭头、判断分支与返工路径的流程图。交付为 `outputs/CutFrame流程图/CutFrame方案流程图.html`，打开的文件更新后需刷新。旧 static/progress 文件仅是旧版，不再作为当前进度依据，不再添加到工具导航。
- 不能因代码写完、导出成功而声称用户业务验收通过。用户确认须有明确反馈。
- 每项保持稳定编号；新增工作新增任务，不静默删掉失败项或未完成项。
- 修改范围需同步阶段、任务及说明，后期功能不要算成当前授权范围。
- 每个环节向用户报告：完成内容、测试证据、待验收项、目前进度、下一步。
- 不上传任何素材，不操作源文件；此看板只记录工作事实。
- 初始化脚本不能用于覆盖已有台账。正常更新必须保留历史。

## 三张表

文件都是 UTF-8 的 JSONL，一行一条，放在 `片段库\`。

### 1. 原片表 `原片表.jsonl`（T01 写）

| 字段 | 说明 |
|---|---|
| 原片ID | 标注库里有的，沿用标注库的 ID；没有的由 T01 新编，前缀 `N` |
| 逻辑路径 | `@shared/拍摄/项目/文件.MOV` 这种写法，和陈瀚文流程包一致，不带 IP 和盘符 |
| 标注库ID | 对不上的留空 |
| 镜序素材ID | 镜序里的 asset_id，对不上的留空 |
| 字节数、修改时间 | 用来确认是同一个文件 |
| 时长、宽、高、旋转角度、画幅 | 画幅：竖 / 横。镜序只用竖屏原片 |
| 来源类型、项目名、目录原名 | 总纲 A2 |
| 可用状态、目录限制原文 | 总纲 A3 和词表第四节 |
| 重复组 | 同内容的副本归一组，组内只有一条进入选材 |
| 声音 | 总纲 C4，沿用标注库 |

### 3. 使用记录 `使用记录.jsonl`（T09 写）

## 和另外两个系统怎么对上

| 我们的字段 | 陈瀚文流程包里的对应 | 镜序里的对应 |
|---|---|---|
| 逻辑路径 | `shots[].source` | 素材的相对路径 |
| 起秒、止秒 | `source_start`、`source_duration` | 候选的 start、end |
| 身份段 | `people_basis`、`names_presenter`；要求有准确的人物审批 | “已确认片段”里的人物事实；只认人工确认的具体时间段 |
| 材料类目、依据等级 | `material_basis`、`asserts_material`；要求有准确的材料审批 | 微陶泥身份只认人工确认的片段或可靠施工记录 |
| 画面类型、主动作、空间、阶段 | 逐镜审核的七项里的空间、阶段、动作、证据 | 检索规则里的动作、施工部位 |
| 使用记录 | `history.json`（按源文件和路径查重） | 检索时的排除清单、采用和评价记录 |
| 瑕疵、可用状态 | 画面与字幕检查里的淘汰项 | 评价原因代码 |

**两处口径不同，等三方定：**

1. **阿明的身份。** 镜序现在只认“人工确认的具体时间段”，明确禁止靠脸或衣服推断。我们这边李康已同意多一个来源：本机人脸比对程序判为“像阿明”（验证过的 28 段全对）。片段库会把来源写清，镜序可以选择只用“人工确认”这一级。
2. **滚涂和刷涂。** 镜序规则写的是“刷子刷涂不是滚涂”。我们的画面类型把滚筒和刷子都归在“施工·滚涂”，在主动作里再分“滚涂”和“刷涂”。给镜序的数据按主动作给，两边就对得上。

## 检索的输入和输出（T08 实现）

输入：

- 文案句，或观点清单里的素材类别
- 需要的时长
- 账号（用来定城市、出镜人）
- 排除清单（本片已用的、近期用过的原片）
- 身份和材料要哪一级的依据

输出，每个候选一条：

- 片段ID、逻辑路径、起止秒、拼图路径
- 满足了对照表里的哪些条件，哪些没满足
- 身份和材料的依据等级
- 近期使用情况
- 审核状态

检索只给候选，采用由人在镜序或流程包里决定。
